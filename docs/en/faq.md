### FAQ: recording with Voice PE {#faq-voice}

<div class="table"><table>
<tr><th>Symptom</th><th>Cause and solution</th></tr>
<tr><td>“Too long, say just the word.” — often, especially with background noise</td><td>an older integration counted background noise and the end of the instruction as speech. Install the current integration and <strong>restart Home Assistant</strong>. The word is now detected relative to the background level, so recording with the TV or talking in the background is fine (and useful)</td></tr>
<tr><td>“Too much noise, speak louder or closer.”</td><td>the word is less than 8 dB louder than the background — move closer, speak clearly or turn the noise down. Some noisy takes are welcome, but the word has to stand out</td></tr>
<tr><td>a “beep” or the end of the instruction at the start of takes</td><td>Voice PE opens the microphone about 0.4 s before playback ends. The current integration adds 0.6 s of silence after the signal and cuts such sound from the start of a take. Older takes: listen to them in the studio (Recordings → All recordings), delete the ones with a beep and record again</td></tr>
<tr><td>no “speak now” signal (beep)</td><td>in HA: device “Wake Word Recorder” → entity “Speak now signal” (Beep / Announcement chime / Off). The “Wake word recording” pipeline must speak with the “Wake Word Recorder” voice — the integration sets this itself after an HA restart</td></tr>
<tr><td>integration changes have no effect after installing</td><td>Home Assistant loads integrations only at start — restart it (Settings → System → Restart)</td></tr>
<tr><td>after recording, Voice PE does not respond as usual</td><td>the session did not end cleanly and the device stayed on the recording pipeline — end the session or pick the usual assistant in the device settings</td></tr>
</table></div>


### FAQ: the studio — errors and messages {#faq-panel}

<div class="table"><table>
<tr><th>Symptom</th><th>Cause and solution</th></tr>
<tr><td>a further run (from the saved state) first spoils the result: AVR drops as low as 0.07, then comes back</td><td>a further run continues from the weights of the previous one and started again at the learning rate 0.001, which shook the learnt model. Now a further run starts at 0.0003 and ends at 0.0001 (<code>FINE_TUNE</code>); the first run of a word is unchanged (0.001 → 0.0003 → 0.0001)</td></tr>
<tr><td>advice: “Raise the negative weight from 30 to 60” although at another cutoff it misses too many words</td><td>when each goal can be met on its own (at a different cutoff) but not both together, doubling the weight trades one problem for the other. Now the studio then looks at the most balanced cutoff and, when both goals are about as far, advises more steps instead of another weight</td></tr>
<tr><td>What does “at cutoff 0.93”, “cutoff 0.99” mean?</td><td>the model keeps saying how sure it is that it hears your word (0 to 1); the cutoff is the line from which it wakes. Cutoff 0.99 = it wakes only when 99% sure: rarely by itself, but sometimes it does not react to the word. Cutoff 0.93 = it reacts more readily: misses less, wakes without a reason more often. You enter the cutoff in Training → Evaluation and export (“Cutoff”) — take the one from the “Final test (best cutoff)” column in Training → Models</td></tr>
<tr><td>Stage: “done — copy the household folder back to the Mac and run 'wakeword evaluate &lt;word&gt;' and 'wakeword export'”</td><td>the last line of the training script, written for the command line. The studio shows “Training finished — compare the models in Training → Models, choose the best one and export it in Evaluate and export.” instead. Nothing has to be copied: the data is already on the machine. On the command line <code>wakeword evaluate</code> and <code>wakeword export</code> do the same</td></tr>
<tr><td>“Home Assistant 404: no recordings API - update the Wake Word Recorder integration and restart HA”</td><td>the integration in HA is older than the studio — update it in HACS and restart HA</td></tr>
<tr><td>“Home Assistant 401: the token is wrong or expired” / “403: … not an administrator”</td><td>the token in Settings → Home Assistant is wrong or belongs to an ordinary user — make a new long-lived token on an administrator account and save it in the studio</td></tr>
<tr><td>“Saved here, but not sent to Home Assistant: …”</td><td>household.yaml was saved in the household folder, but HA did not answer (restarting, no network) — the satellites still ask for the old people/words. When HA is back: save again or click “Sync with HA” in Training → Data and preparing</td></tr>
<tr><td>advice after training: “Lower the negative weight” although the model wakes falsely more than once an hour</td><td>a bug of the advice: it counted the cutoff 1.0 at which the model never wakes (misses 100% of words, 0 false wakes) — that cutoff was always “quiet”, so the advice always said lower the weight. Now it is left out, and when neither goal is met the studio takes the most balanced cutoff and tunes the side much further from its goal (e.g. 8% missed at 1.1 false wakes/h → raise the weight 20 → 30)</td></tr>
<tr><td>the list of ElevenLabs takes stays empty for long, only “Loading…” shows</td><td>with a few thousand takes in hundreds of folders, just reading the list took about a minute. Now “Generate takes” keeps a list in <code>data/elevenlabs/&lt;word&gt;/index.json</code> and the list reads just that file (about 0.2 s). Older takes without the list, or takes changed by hand: the list is rebuilt once on the first load, then it is fast</td></tr>
<tr><td>the “Prepare” log does not mention ElevenLabs — are the takes trained on?</td><td>they are when <code>data/elevenlabs/&lt;word&gt;</code> exists (the <code>elevenlabs</code> set in <code>features.json</code>). The log says so: “hej_jarvis: ElevenLabs 2928 takes from 324 voices”, or “none” when there are none</td></tr>
<tr><td>ElevenLabs: generation stops; “400: Voice '…' is not fine-tuned and cannot be used.”</td><td>a professional Voice Library voice its author did not finish — ElevenLabs does not speak with it through the API. “Generate takes” skips such a voice (also on 404 “voice not found”), keeps it in <code>data/elevenlabs/account.json</code> and goes on; at the end the log says how many voices really have takes. In Synthetic voices → ElevenLabs such voices leave the list and appear in a separate “Unavailable voices” section with the reason; voices chosen before are unticked with “Untick them”. The counter “Voices with takes: X of Y chosen” shows what is on disk</td></tr>
<tr><td>ElevenLabs: generation stops after a few dozen takes; “409: Multiple voice additions/deletions for the same voice were called at the same time. Please retry shortly.”</td><td>a Voice Library voice is added to the account on its first API use; several requests for the same voice at once collided. Now the studio sends the parallel requests to different voices in turn, and on a 409 it waits and tries again. Click “Generate takes” again — the takes made so far stay and generation resumes where it stopped. Such voices do not take custom voice slots</td></tr>
<tr><td>ElevenLabs: Test plays nothing; “402: Free users cannot use library voices via the API”</td><td>on the free plan the ElevenLabs API speaks only with the account's premade voices and your cloned/generated ones; Voice Library voices (also those added to the account) need Starter or higher. The studio learns the plan from this error (or reads it when the key has the User — Read permission): it marks such voices “paid plan”, hides them by default (“only usable on my plan”) and does not generate with them; the error stays on the voice card. Test saves no file — it plays the take in the browser right away</td></tr>
<tr><td>ElevenLabs: the voice previews are in English — do these voices speak Polish?</td><td>library voices fetched for PL are verified in Polish by ElevenLabs (e.g. 324 native Polish speakers and about 180 from other languages); the English previews came mainly from the account's premade voices, which have no Polish. Click “Sync voices” again — every voice is marked (native PL / EN → PL / EN · no PL), the preview is in Polish, and by default the list shows only voices speaking Polish. Still use Test with your “how it sounds” before choosing</td></tr>
<tr><td>ElevenLabs: “Sync voices” shows nothing; “401: The API key you used is missing the permission voices_read”</td><td>the key has limited permissions. On elevenlabs.io → Developers → API Keys edit the key and enable Voices — Read (voice list), Voices — Write (only “add to my voices”) and Text to Speech — Access (Test, Generate); save and click “Sync voices” again — the key in the studio stays. The error shows in Synthetic voices → ElevenLabs, not only in a toast</td></tr>
<tr><td>ElevenLabs: “ElevenLabs 401: Invalid API key” or “no ElevenLabs API key”</td><td>the key is wrong or missing — Synthetic voices → ElevenLabs → paste the key from elevenlabs.io → Developers → API Keys (Voices and Text to Speech permissions) → “Save the key”. The key lives only on the GPU machine, in <code>docker/config/elevenlabs.json</code> (in the container <code>~/.config/wakeword/elevenlabs.json</code>)</td></tr>
<tr><td>ElevenLabs: Test reports an error about the voice (e.g. 404, “voice not found”)</td><td>the library voice cannot be used without adding it to the account — click “add to my voices” on its card (it takes a voice slot of the plan) and try again</td></tr>
<tr><td>ElevenLabs: “quota_exceeded” or error 429</td><td>the monthly character quota is used up or too many requests at once — check the account; “Generate takes” can run again, finished takes are skipped</td></tr>
<tr><td>I generated ElevenLabs takes but training does not use them</td><td>the training config includes <code>data/elevenlabs/&lt;word&gt;</code> only when it exists at Prepare — click “Prepare” (Training → Data and preparing), then “Start training”</td></tr>
<tr><td>I added voices in Synthetic voices → Piper voices and clicked Prepare, but there are no samples of them</td><td>“Prepare” only writes the synthesis script with the new voices; the clips are made at the start of “Start training”. Order: Save → Prepare → Start training. After the synthesis stage in the log the samples show up by themselves in Synthetic voices → Samples to listen to — nothing to fetch. Until then the list shows them as “chosen — made at “Start training” (Prepare only writes the script)”</td></tr>
<tr><td>the samples list shows voices I unticked</td><td>these are samples of the previous synthesis — marked “unticked — goes away with the next synthesis”. After Prepare → Start training the synthesis moves their groups to <code>data/backup/</code> and they leave the list</td></tr>
<tr><td>“Prepare” fails or says no word has all its takes</td><td>first tick the words in “Words to train” at the top of Training → Data and preparing, then click “Prepare”. With nothing ticked only words with all takes are prepared. Missing takes show on the word chips (e.g. <code>tomek 9/12</code>) — record the rest or tick “even with missing recordings”</td></tr>
<tr><td>I recorded the 30 min of background after “Prepare”</td><td>the training config includes <code>data/background</code> only if it exists when preparing — click “Prepare” again</td></tr>
<tr><td>“Save or discard your changes first.” when changing a word id</td><td>changing the id moves files on disk, so the household must be saved — click “Save” or “Discard” in the top bar and try again</td></tr>
<tr><td>Home Assistant still shows the old word (e.g. <code>optimus_prime</code>) after its id was changed to <code>hej_optimus</code></td><td>household.yaml did not reach HA (e.g. HA did not answer). Click <strong>Sync with HA</strong> in Training → Data and preparing (or <code>wakeword ha-push</code>). Normally a change of id sends the file itself, and the studio says so when HA does not answer</td></tr>
<tr><td>“Household” column: “not measured — “Test at home””</td><td>the model was made before this version or held-out takes or background were added since its test. When takes were added, first “Sync with HA” (Training → Data and preparing), then “Test at home” in Training → Models</td></tr>
<tr><td>“Household” column: “no held-out takes or test background”</td><td>the word has no held-out takes (Training → Data and preparing → “Prepare”) or <code>data/background</code> has fewer than 2 background recordings — record the home background (Recordings → Home background, chapter 7)</td></tr>

### FAQ: how to do it in the studio {#faq-howto}

<div class="table"><table>
<tr><th>Question</th><th>Answer</th></tr>
<tr><td>Where is this guide in the studio?</td><td><code>?</code> in the top bar opens the documentation in a new tab, and <code>?</code> on each card opens its help</td></tr>
<tr><td>How long will training take? What percent of the steps is done?</td><td>Training → Live progress: <em>step X of Y · percent · about … left</em> (from the first 500 steps). Earlier stages (installation, downloads, synthesis, features) — the time table in chapter 9; the “Training log” shows what is going on</td></tr>
<tr><td>Should I train once more with other settings?</td><td>after the final test read the “What next” box in Training → Live progress — it says whether it is done and, if not, what to change; “Set these values” fills them into Training → Parameters and start. The previous model stays in <code>data/backup/training-…</code></td></tr>
<tr><td>What do “Steps” and “Negative weight” mean?</td><td>Steps — how many training steps (empty = 20,000; a next run continues from the saved state). Negative weight — empty = 20; higher = fewer false wakes but the word is missed more often</td></tr>
<tr><td>What does “Only convert the best weights” do?</td><td>without training it makes the model from the best state so far — after Stop or when training broke off near the end</td></tr>
<tr><td>How do I copy a log?</td><td>the “Copy” button in Overview → Command output and at the “Training log”; for the training log the whole log is copied, not only the visible end</td></tr>
<tr><td>How do I hide what I do not need?</td><td>fold the groups of the tree with a click (or “Fold all”), and the left and right columns with “Fold the left column” / “Fold the right column”</td></tr>
<tr><td>Does closing the browser stop training?</td><td>no — training runs in the container on the GPU machine; when you open the studio again it shows its progress and log. Only “Stop” stops it (and a restart of the container, e.g. <code>make deploy</code>)</td></tr>
<tr><td>How do I rename a word?</td><td>Household → Words: type the display name directly; the id (folder name) is changed with “change” — it moves the recordings, ElevenLabs takes, models and synthetic speech and puts Prepare's files aside in <code>data/backup/</code>; then Prepare again</td></tr>
<tr><td>How do I reorder people or words?</td><td>Household → People or Words: drag the card by its handle and click “Save” — <code>household.yaml</code> follows</td></tr>
<tr><td>How do I record a word again?</td><td>Recordings → All recordings → the word: tick the failed takes → “Delete selected” (files go to <code>data/backup/deleted-…</code>) and record again — new numbers never overwrite old ones</td></tr>
<tr><td>Do I need a Hugging Face token?</td><td>no — it only speeds up downloads. Set it in Settings → Machine and HF token; it stays on the GPU machine, and below the field you see “A token is set on the GPU machine”</td></tr>
<tr><td>How do I refresh the screenshots in this guide?</td><td><code>make screenshots</code> (made-up household, Google Chrome)</td></tr>
</table></div>

<tr><td>Lost the studio's login or password</td><td>it is in <code>docker/config/env</code> on the machine (<code>WAKEWORD_UI_AUTH=admin:password</code>); <code>docker/install-ubuntu.sh --show-login</code> shows it. To change it: edit the file and <code>docker compose -f docker/compose.yaml restart</code> — everybody is logged out</td></tr>
<tr><td>“Too many attempts - try again in 60 s”</td><td>5 wrong passwords from one address: the studio waits 60 s (not a permanent ban). Check the password in <code>docker/config/env</code></td></tr>
<tr><td>The container restarts over and over, the log says <code>error: WAKEWORD_UI_AUTH must be user:password</code></td><td><code>docker/config/env</code> is missing or wrong — run <code>docker/install-ubuntu.sh</code> (it writes the login) or put <code>WAKEWORD_UI_AUTH=admin:password</code> in it</td></tr>
<tr><td>“The studio does not answer - is the container running?” on the login page</td><td>the container is off or still starting: <code>make docker-logs</code> on the machine; Docker starts it with the machine (<code>restart: unless-stopped</code>, <code>systemctl is-enabled docker</code>)</td></tr>
<tr><td><code>make status</code> or the installer: <code>TensorFlow: no GPU - training would run on the CPU</code>, although <code>nvidia-smi</code> in the container shows the card</td><td>TensorFlow did not load its CUDA libraries (the log with <code>TF_CPP_VMODULE=dso_loader=2</code>: <code>Could not load dynamic library 'libcusolver.so.11'</code>). That was the image of 0.2.0: TensorFlow 2.21's <code>libtensorflow_framework.so.2</code> has no <code>nvidia/cusolver/lib</code> in its paths. From this version the image sets <code>LD_LIBRARY_PATH</code> to that folder (and takes torch from the CUDA 12 index) — <code>make deploy</code> is enough. Check: <code>docker/install-ubuntu.sh --gpu-check</code> on the machine</td></tr>
<tr><td>“GPU: none” or <code>TensorFlow does not see a GPU</code> in the training log</td><td>the container does not see the card: <code>nvidia-smi</code> on the machine, then the NVIDIA Container Toolkit (<code>sudo nvidia-ctk runtime configure --runtime=docker</code>, restart Docker) and <code>make docker-up</code>. Check: <code>docker compose -f docker/compose.yaml exec studio nvidia-smi</code></td></tr>
<tr><td><code>No space left on device</code> while building the image or training</td><td>the image is ~12 GB, <code>docker/data/work</code> ~30 GB, plus recordings and models — about 60 GB is needed. Remove old images: <code>docker image prune</code></td></tr>
<tr><td>Home Assistant answers <code>403</code> to everything from the machine (<em>Banned IP</em> in HA's log)</td><td>a series of rejected tokens (401) banned the machine's address (<code>ip_ban</code>). The studio stops asking HA after the first 401; lift the ban in <code>/config/ip_bans.yaml</code> and restart HA, then type a good token (Settings → Home Assistant → Save)</td></tr>
<tr><td>“household.yaml changed outside the editor…”</td><td>the file changed since the draft started (e.g. fetched from HA). “Save” asks for “Save anyway” — the previous version stays in History; or “Discard” and start from the current file</td></tr>
<tr><td>A training stopped after an update (<code>make deploy</code>)</td><td>restarting the container stops the training — update when nothing is training; the next training continues from the saved state</td></tr>
<tr><td>A new or changed chapter (e.g. Studio, “Training well”) is not on the home documentation site, no screenshots</td><td>the documentation is a MkDocs site built from <code>docs/en</code> and <code>docs/pl</code>: check it here (<code>make docs</code> or <code>make docs-serve</code>), then <code>make deploy</code> in <code>docs-hub</code> — docs-hub builds it itself (<code>make docs-build</code>). A new chapter must also go to <code>nav</code> in <code>mkdocs.yml</code> (a test checks it)</td></tr>
<tr><td><code>put GPU_HOST = user@machine in ~/.config/gpu-studio/host.mk</code> after <code>make install</code>, <code>deploy</code>, <code>login</code>, <code>logs</code> or <code>status</code></td><td>the GPU machine's address is now shared by every studio: put it once in <code>~/.config/gpu-studio/host.mk</code> (e.g. <code>GPU_HOST = user@192.168.1.21</code>). <code>GPU_HOST</code> in <code>Makefile.local</code> works too, but only for this repository</td></tr>
<tr><td><code>Docker is not running: install and start Docker Desktop</code> after <code>make demo</code>, <code>make docs</code> or <code>docs-serve</code></td><td>the demo and the documentation run in a container: install <a href="https://www.docker.com/products/docker-desktop/">Docker Desktop</a>, start it (the whale icon in the menu bar) and run <code>make demo</code> again. Without Docker, a developer can use <code>make demo-local</code> (needs <code>make setup</code>)</td></tr>
<tr><td><code>uv not found: curl -LsSf https://astral.sh/uv/install.sh | sh</code> after <code>make setup</code>, <code>test</code> or another development command</td><td>the developer's environment is made by <a href="https://docs.astral.sh/uv/">uv</a>, which fetches Python 3.12 by itself (no <code>brew install python</code>): run the command from the message once, open a new terminal, repeat. Only trying the studio does not need it: <code>make demo</code></td></tr>
<tr><td><code>port 8765 is taken by another program</code> from <code>docker/install-ubuntu.sh</code></td><td>another program holds the port, e.g. the old training panel from before 1.0.0 still running on the machine. <code>ss -ltnp 'sport = :8765'</code> shows the process — stop it and run the installer again.</td></tr>
<tr><td>“No answer from the studio in … s - it may be busy; it is asked again by itself.”</td><td>the studio's server did not answer within the time limit (the state: 20 s, other calls: 150 s) — usually a very busy machine or a slow Home Assistant. The page does not hang and asks again by itself; when the message stays, check <code>make status</code> and <code>make logs</code></td></tr>
